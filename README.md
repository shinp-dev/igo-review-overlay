# Igo Review Overlay — 囲碁クエスト 9路振り返り

囲碁クエストの **9路盤専用** Android オーバーレイアプリです。Android 14 以降向けの初期実装で、局面をスクリーンキャプチャから読み取り、KataGo の候補手と評価値を交点内に描画します。19路・棋譜一括解析・悪手集計は対象外です。

**現在の実装範囲:** Android の設定画面、MediaProjection の画面共有、盤面枠の手動調整、81交点の石と最終着手の丸印の認識、局面変更時の再解析、勝率・目数差と候補手1〜5件の描画、盤面右の余白タップによる表示切替、終了通知、PC上の KataGo に問い合わせるブリッジ。

**重要:** KataGo はまだ APK に内蔵されていません。KataGo 実行ファイルとニューラルネットワークモデルを入手し、PC などで別途動かす必要があります。Android 実機での動作確認と APK ビルド検証は未実施です。

## 起動方法

### 1. PC側のKataGoを起動

KataGo 公式の `analysis` モードとモデル、解析用設定ファイルを用意します。Python 3.10+ だけでブリッジを起動できます（追加パッケージ不要）。

```bash
python bridge/katago_bridge.py \
  --katago /path/to/katago \
  --config /path/to/analysis.cfg \
  --model /path/to/model.bin.gz \
  --host 0.0.0.0 --port 8765 \
  --token YOUR_LONG_RANDOM_TOKEN \
  --perspective BLACK
```

`--perspective` は KataGo の config の `reportAnalysisWinratesAs` と一致させてください。公式の `analysis_example.cfg` は通常 `BLACK` です。設定ファイルで `SIDETOMOVE` に変更した場合はコマンド側も `SIDETOMOVE` にします。ブリッジは勝率と目数差を**次に着手する側**に正規化します。

PCとAndroidを同じ信頼できるLANに置き、PCのLAN内IPを確認します。PCのファイアウォールでポート8765を許可する必要があります。平文HTTPですのでインターネットに公開しないでください。LAN外で使う場合は安全なトンネルとTLSを別途用意してください。ループバック以外の待受ではトークンを必須にしています。

### 2. Androidをビルド

Android Studioで開くか、JDK 17・Android SDK 36を入れて以下を実行します。

```bash
./gradlew :app:assembleDebug
./gradlew :app:installDebug
```

アプリの「KataGo接続先」に `http://192.168.x.x:8765` 形式でPCのURLを入力し、上の `--token` と同じトークンを設定します。候補数、探索回数、勝率・目数差、自動更新、不透明度を選び、保存します。

「盤面解析を開始」を押し、他アプリの上への表示許可と、画面全体の共有を許可します。囲碁クエストの9路振り返り画面を開いてください。画面共有が止まると解析も終了します。

### 3. 盤面枠と右端操作

- **左上↖・右下↘** は、囲碁盤の木枠ではなく、9×9の **最外交点** に合わせます。スクリーンショット例では左右おおむね x=44〜647、上下 y=364〜974（691×1536px）に相当します。
- **盤面右側の細い色付き帯** は評価値オン／オフ専用です。帯以外の盤面タップは囲碁クエスト側に通します。右余白が狭すぎると帯を出せないので、盤面枠を少し左へ調整してください。
- **手番: 自動／黒／白** は丸印で手番が判別できない局面向けです。「解析」は手動再実行、「終了」は画面共有と重ね合わせを終了します。
- オーバーレイ表示のオン／オフは保存され、再起動後も維持されます。アプリ内の設定画面では、盤面枠を初期位置に戻せます。

## 技術・制限事項

- 読み取り範囲は9路の最外交点で、交点間を8等分します。白石内の黒丸・黒石内の白丸で最終着手を判定し、その**反対側**を次の手番として解析します。マーカーがない場合は直前局面との差分から手番を推定します。再生ボタンの操作・監視は行いません。
- 認識は現在局面のみで、過去の棋譜を復元しません。KataGo へは `initialStones` と `initialPlayer` を送るので、コウ・スーパーコウ・手順履歴を必要とする局面では正確な合法手や評価を保証できません。着手履歴は将来の拡張対象です。
- ルールは中国ルール、コミ7目で固定です。KataGoの解析応答は近似値で、探索回数を増やしても確定値にはなりません。
- オーバーレイの描画ウィンドウは非タッチ、右端の帯と操作パネル・移動ハンドルだけがタッチを受けます。
- Androidの画面共有同意は起動するたびに必要です。画面キャプチャ画像やアカウント情報をブリッジに送信しません。石配置のみ送信します。
- 解析は終局後の振り返りを意図しています。対局中の手助けとして使わないでください。
- KataGoおよびニューラルネットモデルは別途取得が必要です。KataGoのソースやモデルの再配布は行っていません。

## 簡易検証

```bash
cd bridge
python -m unittest test_bridge.py
```

動作確認の優先順位: ①実機で画面共有と9路の読み取り、②最終着手マーカーによる手番、③右側帯のタップと通常盤面操作の透過、④長時間のKataGo再解析とアプリのメモリ利用。
